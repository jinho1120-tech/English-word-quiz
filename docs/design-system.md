# 디자인 시스템 및 테마색 사용 지침

English-word-quiz의 부모 관리자 앱과 자녀 학습 앱이 공유하는 공식 디자인 기준이다. UI를 수정하거나 새 기능을 추가하는 모든 AI 개발 도구와 개발자는 이 문서를 먼저 확인한다.

## 1. 핵심 원칙

**사용자의 테마색 선택은 자유롭게, 앱의 색상 사용 규칙은 일관되게 유지한다.**

- 오른쪽 상단 팔레트에서 프리셋 또는 직접 입력한 HEX 색상을 선택할 수 있다.
- 원본 HEX와 라이트/다크/시스템 모드는 기존 브라우저 로컬 저장 방식과 키를 유지한다. 부모 화면과 자녀 화면이 같은 브라우저 저장값을 공유하는 현재 동작을 바꾸지 않는다.
- 선택한 색상이 현재 배경에서 WCAG 일반 텍스트 대비 4.5:1을 충족하지 못하면 렌더링용 강조색의 명도를 필요한 만큼 조정한다.
- 저장된 원본 색상은 바꾸지 않는다. 접근성 보정은 렌더링에만 적용한다.
- 강조색 배경 위의 글자는 검정/흰색 중 대비가 높은 색을 자동 선택한다.
- 시스템 모드에서는 OS의 라이트/다크 설정이 바뀔 때 강조색 대비를 다시 계산한다.

## 2. 의미별 색상 토큰

| 토큰 | 용도 |
| --- | --- |
| `primary` / `primary-foreground` | 주요 실행 버튼, 강조 액션, 진행 상태 |
| `primary-container` / `primary-container-foreground` | 선택 메뉴·탭·필터의 연한 배경 |
| `child-accent` / `child-accent-foreground` | 자녀 학습 화면의 강조 아이콘과 퀴즈 강조색 |
| `theme-outline` | 테마색이 의미 있는 활성 테두리 |
| `background`, `card`, `foreground` | 중립 배경, 카드, 기본 글자 |
| `muted`, `muted-foreground`, `border` | 비활성 상태, 보조 정보, 일반 테두리 |
| `destructive` | 삭제·오류·위험 동작 |

기본 사용 예시:

```tsx
className="bg-primary text-primary-foreground"
className="bg-primary-container text-primary-container-foreground"
className="border border-border bg-card text-card-foreground"
className="text-muted-foreground"
```

`app/globals.css`의 `@theme inline`과 CSS 변수 정의가 Tailwind 색상 유틸리티의 기준이다. 토큰을 추가하거나 이름을 바꾸면 매핑과 이 문서를 함께 갱신한다.

## 3. 테마색 적용 대상

적용:
- 화면에서 가장 중요한 주요 실행 버튼
- 현재 활성화된 탭, 메뉴, 과목, 필터
- 학습 진행률과 진행 바
- 활성 입력 상태와 포커스 표시
- 자녀 학습 화면의 주요 강조 아이콘

남용하지 않음:
- 앱 전체 배경과 일반 카드
- 일반 제목·본문·설명
- 비활성 버튼과 메뉴
- 일반 구분선과 보조 정보
- 쿠폰 일러스트 및 쿠폰 자체 디자인
- 게임 화면의 캐릭터·배경·아이템 디자인

주요 액션과 선택 상태가 여러 개의 강한 색상으로 경쟁하지 않도록 한다. 장식 목적의 강조색 사용은 최소화한다.

## 4. 의미 색상은 테마색과 분리

- 성공/정답/완료: 녹색 계열
- 오류/오답/삭제/위험: 빨간색 계열
- 경고/주의: 주황색 또는 황색 계열
- 정보: 정보 전달용 색상

사용자 테마색을 바꿔도 의미 색상은 변경하지 않는다. 색상만으로 의미를 전달하지 말고 아이콘, 텍스트, 상태 표시를 함께 사용한다.

자녀 과목별 사용자 지정 색상과 게임 고유 색상도 별도의 의미를 가진 색상 체계이므로 테마색으로 덮어쓰지 않는다.

## 5. 대비와 접근성

- 일반 텍스트: 최소 4.5:1
- 큰 텍스트: 최소 3:1
- 의미를 전달하는 아이콘·컨트롤 경계: 최소 3:1
- 선택 상태는 색상뿐 아니라 배경·테두리·아이콘·텍스트 등으로도 식별 가능해야 한다.
- 테마색 배경 버튼은 `primary-foreground` 또는 `child-accent-foreground`를 사용하며 흰색 글자를 무조건 고정하지 않는다.
- 원본 선택 색상은 보존하고, 대비를 만족하지 못할 때 렌더링용 강조색의 명도를 보정한다.
- 대비 계산은 sRGB 상대 휘도와 WCAG 대비율을 사용한다.

## 6. 투명도와 전역 색상 변경

CSS 변수 형태의 색상에 HEX 알파 접미사를 문자열로 덧붙이지 않는다. 아래처럼 사용한다.

```ts
const tint = `color-mix(in srgb, ${accent} 10%, transparent)`
```

전역 테마 변수를 런타임에 변경하는 코드는 `components/child-profile-settings.tsx` 한 곳에 둔다. 기능 컴포넌트에서 `document.documentElement.style.setProperty`로 전역 테마 토큰을 직접 변경하지 않는다.

새 UI는 임의의 HEX/Tailwind 색상 대신 의미 토큰을 사용한다. 단, 상태 색상, 과목 사용자 지정 색상, 쿠폰/게임 고유 디자인은 예외로 허용한다.

## 7. 부모 앱과 자녀 앱

두 앱은 동일한 테마색 토큰과 대비 규칙을 공유한다.

- 부모 앱: 정보 전달과 관리 작업이 중심이므로 중립 배경/카드를 우선하고, 주요 액션과 활성 상태에만 테마색을 사용한다.
- 자녀 앱: 학습 행동, 활성 탭, 선택 과목, 진행 상태를 조금 더 분명하게 강조할 수 있다. 게임과 쿠폰의 고유 색상은 유지한다.
- 두 앱의 분위기는 달라도 버튼·선택 상태·텍스트 대비 규칙은 동일하다.

## 8. 테마 팔레트 경험

- 기존 팔레트 위치와 기존 사용자 선택값을 유지한다.
- 프리셋과 직접 HEX/컬러 피커를 모두 허용한다.
- 선택 즉시 화면 미리보기를 갱신한다.
- 주요 버튼, 선택 메뉴, 진행 표시 미리보기를 제공한다.
- 기본 테마 복원 기능을 제공한다.
- 원본 선택 색상과 실제 접근성 보정 색상이 다를 수 있음을 안내한다.
- 테마 설정 저장 방식이나 사용자 범위를 임의로 바꾸지 않는다.
